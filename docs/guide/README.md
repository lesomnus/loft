# 안내서

Loft를 쓰는 사람마다 하루가 다릅니다. 자기에게 맞는 안내서부터 읽습니다.

| 누구 | 안내서 |
| --- | --- |
| 구성원: 빌리고, 예약하고, 받은 것을 확인하는 사람 | [구성원](member.md) |
| 매니저: 자산을 등록하고 건네고 돌려받는 사람 | [매니저](manager.md) |
| 관리자·소유자: 워크스페이스와 사람, 설정을 맡은 사람 | [관리자·소유자](admin.md) |
| 감사자: 기록을 읽고 점검하는 사람 | [감사자](auditor.md) |
| 결제 담당: 워크스페이스의 요금을 내는 사람 | [결제 담당](payer.md) |
| 배포 운영자: 서버를 띄우고 지키는 사람 | [배포 운영자](operator.md) |
| 모두: 터미널과 비서(MCP) | [터미널과 비서](terminal.md) |

역할은 워크스페이스마다 정해집니다. 한 계정이 이 워크스페이스에서는 매니저이고 저 워크스페이스에서는 구성원일 수 있습니다. 결제 담당과 배포 운영자는 역할이 아닙니다. 결제 담당은 계정 자신이 하는 일이고, 배포 운영자는 서버 상자에서 일합니다.

## 따라 하기: 체험용 워크스페이스

안내서의 예는 모두 `init --demo` 가 만드는 워크스페이스를 씁니다. 띄우는 법은 [루트 README](../../README.md#바로-써-보기)에 있습니다. 소유자는 `admin` / `admin1234`, 나머지는 모두 비밀번호 `demo1234` 입니다.

- **워크스페이스**: 우리 회사(주소 `/@loft`)
- **조직**: 본사 아래 개발팀, 디자인팀, 운영팀, 영업팀, 경영지원팀. 팀마다 10명씩 50명입니다. 아이디는 `이름-성`(`minjun-kim`), 이메일은 `아이디@example.com` 입니다.
- **역할별 사람**

  | 역할 | 사람 |
  | --- | --- |
  | 소유자 | 관리자 `admin` |
  | 관리자 | 이건우 `gunwoo-lee` (경영지원팀) |
  | 감사자 | 박나은 `naeun-park` (경영지원팀) |
  | 매니저 | 김민준 `minjun-kim` (개발팀), 김예린 `yerin-kim` (디자인팀), 김다은 `daeun-kim` (운영팀), 김지아 `jia-kim` (영업팀), 김지민 `jimin-kim` (경영지원팀) |
  | 구성원 | 그 밖의 모두. 예: 이하은 `haeun-lee` (개발팀), 이지우 `jiwoo-lee` (디자인팀), 박예준 `yejun-park` (디자인팀), 이현우 `hyunwoo-lee` (영업팀) |

- **공간**: 본사(SP-01) › 3층(SP-02)에 회의실 A(SP-04, 8명), 회의실 B(SP-05, 4명), 개발팀·디자인팀 사무실. 4층(SP-03)에 대회의실(SP-08, 20명), 운영팀·영업팀·경영지원팀 사무실, 창고(SP-12), 서버실(SP-13).
- **자산**: 140여 개
  - 사람마다 노트북(NB-001~NB-050, "이하은 노트북")과 모니터(MN-001~MN-050). "입사 지급"으로 건넸고, 인수 확인은 아직입니다.
  - 창고에 예비 노트북(NB-051~NB-055)과 업무폰 1~10(PH-001~PH-010). 업무폰 1은 김지아에게 내일까지, 업무폰 2는 이현우에게 2주 동안 빌려 주었습니다.
  - 촬영 키트(KT-001): 촬영용 카메라(CM-001), 표준 줌 렌즈(LN-001), 삼각대(TR-001)가 필수 구성품입니다.
  - 빔프로젝터 1·2(PJ-001, PJ-002), 무선 AP 1~4(AP-001~AP-004)
  - 서버실의 서버 랙 A(RK-001)에 웹 서버 1·2(SV-001, SV-002), DB 서버(SV-003), 코어 스위치(NW-001)
- **예약할 수 있는 것**: 회의실 A·B와 대회의실(평일 8시~20시), 촬영 키트, 빔프로젝터 1. 대회의실만 매니저의 승인이 필요합니다.
- **예약**: 개발팀 주간 회의(회의실 A, 김민준, 다음 주 월요일부터 매주 8번), 디자인 리뷰(회의실 B, 김예린), 전사 타운홀(대회의실, 김지민, 승인 대기), 제품 촬영(촬영 키트, 이지우)
- **재고**(창고): A4 복사용지 20박스, AA 건전지 48개, M650 마우스 6개
- **작업**: 박예준 노트북(NB-013)의 배터리 교체(수리 접수), 무선 AP 정기 점검 넷(일주일 뒤, 90일마다)
- **구매**: 모니터 추가 구매(PO-2026-0412). LG 27UP850 5대는 자산으로, 마우스 10개는 재고로 받을 것이고, 아직 입고 전입니다.

## 모두에게 같은 것

### 로그인과 워크스페이스

- 아이디나 이메일로 로그인하고, 어느 워크스페이스인지는 묻지 않습니다. 이메일은 내장 roster면 사람 기록의 이메일이고, 외부 roster면 roster에서 확인된 주소입니다.
- 2단계 인증을 켠 사람은 비밀번호만으로 들어올 수 없고, SSO로 들어옵니다.
- 처음 로그인한 계정이 어느 워크스페이스에도 없으면 자기 워크스페이스가 하나 생깁니다.
- 화면 왼쪽 위의 **워크스페이스 전환기**에서 워크스페이스를 바꾸고, 새로 만들고(+ 새 워크스페이스), 받은 초대와 결제 화면으로 갑니다. 화면의 주소는 `/@<워크스페이스>/...` 입니다.
- 배포가 약관 동의를 묻는다면 처음 들어올 때(그리고 문서의 버전이 바뀔 때마다) 동의 화면을 봅니다. 동의하기 전에는 아무것도 할 수 없습니다. 동의하지 않아도 자기 워크스페이스의 데이터는 내려받을 수 있습니다.

### 알림

화면 위의 종 모양이 알림입니다. 다음 알림은 앱과 함께 메일로도 갑니다.

- 승인 요청(승인하는 사람에게)과 그 결과(요청한 사람에게)
- 반납 연체(가진 사람과 관리하는 사람에게)
- 다가오는 정기 점검(관리하는 사람에게)
- 키트 구성품 충돌과 풀 수량 부족
- 예약이 잡은 것의 분실·불용·폐기와 삭제
- 예약이 잡은 것을 다른 사람이 가지고 나가 있음(대여·지급·연체, 관리하는 사람과 예약한 사람에게)

나머지 알림은 앱에서만 받습니다. 받는 주소는 roster가 확인한 계정의 주소이고, 내장 roster면 사람 기록의 이메일도 씁니다. 주소가 없으면 보내지 않습니다. 메일은 **내 정보**의 "알림을 메일로도 받기"에서 끕니다(`NotificationService.SetMail`). 꺼도 앱 알림은 그대로 옵니다.

### 날짜와 금액

- 날짜와 시각은 브라우저가 어느 시간대에 있든 **그 워크스페이스의 시간대**로 보이고, 입력도 그 시간대로 읽습니다. 소유자가 정하고, 정하지 않으면 배포의 기본(보통 Asia/Seoul)입니다.
- 금액은 그 통화의 최소 단위의 정수입니다(KRW는 원, USD는 센트). 화면에서 12.50달러를 넣으면 1250으로 저장됩니다. 기록된 금액은 기록할 때의 통화 그대로이고, 환산하지 않습니다.

### 같은 이름

사람을 늘어놓는 곳(대여 현황과 그 CSV, 대시보드의 연체, 지급·대여, 예약, 자산 목록과 대장 CSV, 사람 선택, 감사 기록과 접속기록의 구성원)은 같은 이름이 둘 이상이면 이름 뒤에 속한 팀을 붙입니다(`김민준 · 개발팀`). 같은 이름의 팀에도 있으면 사번을, 그것으로도 가를 수 없으면 사람 기록의 ID를 붙입니다. 이메일과 전화번호는 쓰지 않습니다. 이력의 문장과 알림은 이름만 씁니다.

### 실시간

자산 상세, 예약 캘린더, 진행 중인 실사는 다른 사람이 바꾼 것이 새로고침 없이 바로 보입니다.

### 오프라인

연결이 끊겨도 앱이 열리고, 이 브라우저에서 마지막으로 본 화면을 그대로 보여 줍니다(위에 "오프라인 — 마지막으로 본 내용").

- 오프라인에서는 읽기만 하고, 저장은 이유와 함께 거절합니다. 실사 스캔만 모아 두었다가 연결되면 보냅니다.
- **로그아웃하면** 이 브라우저에 보관한 것을 모두 지우고, 같은 주소의 다른 탭도 함께 로그인 화면으로 돌아갑니다.
- **세션이 저절로 끝나면**(유휴, 쿠키를 지움 등) 로그아웃이 아니므로 보내지 못한 스캔은 남겨 둡니다. 같은 사람이 다시 로그인하면 그때 보냅니다. 본 내용과 마지막 로그인 정보는 지웁니다(다시 로그인하면 다시 읽습니다).
- **다른 사람이 로그인하면** 앞 사람의 것은 본 내용도, 보내지 못한 스캔도 남기지 않습니다. 앞 사람의 스캔이 다음 사람으로 보내지는 일은 없습니다. 같은 브라우저의 다른 탭에서 다른 사람이 로그인하면, 남겨진 화면의 호출은 그 사람으로 처리되지 않고 거절됩니다. 화면은 지금 누가 로그인했는지 다시 묻고 그 사람으로 다시 시작합니다.

### 터미널

화면에서 하는 일은 모두 터미널에서도 됩니다. 로그인과 명령의 모양은 [터미널과 비서](terminal.md)에 있고, 안내서마다 그 사람의 명령을 보입니다.
