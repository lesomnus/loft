# 결제 담당 안내서

결제 담당(지불자)은 워크스페이스의 요금을 내는 계정입니다. 워크스페이스 안의 역할이 아니라 계정 자신이 하는 일이라서, 결제 화면(`/billing`, 워크스페이스 전환기의 **결제**)은 어느 워크스페이스에서 열든 같습니다. 배포가 과금을 켜 두었을 때만 결제가 보입니다.

누가 무엇을 내는지는 청구 서비스 [levyan](https://github.com/lesomnus/levyan)의 것이고, Loft는 levyan에 묻고 보여 줄 뿐 결제에 관한 것을 저장하지 않습니다(design 7.9, D63). 이 문서의 예는 체험용 워크스페이스의 구성원 **이하은**(`haeun-lee`)이 소유자의 제안을 받아 "우리 회사"를 내게 되는 흐름입니다.

## 누가 내나

- 처음에는 워크스페이스를 만든 사람이 냅니다. 그다음은 제안을 받아들인 사람입니다.
- 소유자는 **설정 › 결제**에서 구성원에게 결제 담당을 제안하거나, **내가 결제 담당 맡기**로 스스로 맡습니다([관리자·소유자](admin.md#결제-관리자-이상)).
- 결제 담당이 바뀌는 것은 언제나 **이번 기간이 끝난 뒤부터**입니다.
- 결제 담당이 없거나 결제가 실패하면 워크스페이스는 언젠가 제한되고, 더 지나면 읽기 전용이 됩니다(아래 "결제가 실패하면").

## 하루

### 결제 계정 만들기

1. 결제 화면의 **새 결제 계정**에서 나라를 고릅니다. 채널과 통화는 levyan이 나라에 따라 정합니다(한국이면 "MoR (Paddle), KRW").
2. 받는 사람과 사업자 정보(세금계산서에 적을 것)를 적고 **만들기**를 누릅니다. 나중에 **청구 정보 바꾸기**로 고칩니다.
3. 결제 계정에 이름을 붙여 두면 고르는 곳마다 그 이름으로 보입니다. 이름이 없는 결제 계정이 여럿이면 서로 가를 수 있게 표시합니다.
4. 계좌이체로 내는 결제 계정의 사업자 정보는 계약에 따른 것이라 운영자가 바꿉니다. 바꾸려면 운영자에게 알립니다.

### 결제수단 등록

결제 계정의 **결제수단 등록**을 누르면 Paddle의 결제창(`/billing/checkout`)이 열리고, 마치면 결제 화면으로 돌아옵니다. 카드는 levyan이 답하는 종류, 브랜드, 끝 네 자리만 보입니다(예: "카드 visa •••• 4242"). 결제창은 브라우저에서만 엽니다.

### 제안 받아들이기

1. 소유자가 제안하면 결제 화면의 **받은 제안**에 "결제 담당이 되어 달라는 제안을 받았습니다"가 보입니다. 그 워크스페이스의 화면 위에도 "결제 담당 제안을 받았습니다. 결제 화면에서 받아들이기 →"가 나옵니다.
2. **받아들이기**에서 낼 결제 계정을 고릅니다. 아직 정하지 않아도 됩니다.
3. "제안을 받아들였습니다. 이번 기간이 끝난 뒤부터 냅니다."가 나오고, **내는 워크스페이스**에 그 워크스페이스가 생깁니다. 싫으면 거절합니다.

### 내는 워크스페이스

- 워크스페이스마다 어느 결제 계정으로 낼지 바꿉니다("이번 기간이 끝난 뒤부터 이 결제 계정으로 냅니다.").
- **그만 내기**는 이번 기간이 끝나면 더 내지 않는 것입니다("이번 기간이 끝나면 더 내지 않습니다.").

### 청구서와 명세서

- **청구서**: 크레딧이 낸 금액과 청구한 금액이 보입니다. 청구서를 열면 줄마다 그 명세서가 있습니다. 명세서는 levyan이 지불자에게 답하는 것으로, 미터마다 사용량·무료·사용량 크레딧·유료·금액입니다(design 7.12). 지불자가 읽는 것은 그 결제 계정이 그 기간에 낸 명세서이고, Loft가 제품 키로 대신 읽지 않습니다.
- **정정 청구**: 청구서를 바로잡은 것입니다.
- 미터는 활성 자산, 첨부 저장량, 구성원, 이력 보존 기간입니다. 무엇을 어떻게 세는지는 [과금](../dev/billing.md#무엇을-재나)에 있습니다.
- 휴대폰(너비 520px 이하)에서는 청구서와 정정 청구를 표 대신 한 건씩 상자로 보이고, 상자를 눌러 청구서를 엽니다. 화면이 옆으로 밀리지 않습니다.
- 날짜는 브라우저가 어디에 있든 배포의 시간대로 보입니다.

### 크레딧과 잔액

결제 계정마다 다음 청구서가 결제수단보다 먼저 쓸 **크레딧**과 **잔액**이 보입니다.

- 크레딧은 그 결제 계정의 것과 그것으로 내는 워크스페이스의 것이 함께 보입니다. 남은 금액과 만료일이 있고, 30일 안에 만료되면 "곧 만료"입니다.
- 잔액은 그 밖에 받을 돈(0보다 적게 나온 청구서, 정정 청구, 더 낸 것)이고, 만료되지 않으며 크레딧 다음에 씁니다.
- 추가 무료량, 사용량 크레딧, 금액 크레딧은 levyan의 운영자가 줍니다(design 7.11). Loft에는 주는 길이 없고 levyan이 답하는 것을 보이기만 합니다. 수량은 소수점 아래 첫째 자리까지 보이고(0보다 크고 0.1에 못 미치면 "0.1 미만"), 사용량 크레딧은 "자산·월"처럼 미터의 단위에 한 달을 곱한 단위로 말합니다.

### 결제가 실패하면

- 지금 결제할 수 없는 결제 계정(결제수단 없음 같은 것)은 결제 화면 맨 위의 **결제할 수 없는 결제 계정**에 할 일과 함께 모아 보입니다. 그것만으로 제한된 것은 없습니다. 그 워크스페이스의 소유자와 관리자에게도 무엇이 실패하기 전에 알립니다.
- 청구서의 결제가 실패하면 그 결제 계정에 "결제가 실패했습니다. 결제수단을 바꿔 주세요."와 "…까지 결제되지 않으면 제한됩니다."가 나오고, 내가 내는 워크스페이스의 화면 위에도 띠가 나와 결제 화면으로 안내합니다.
- 그날까지 결제되지 않으면 워크스페이스가 **제한**됩니다. 청구되는 것을 늘리는 일(자산 등록, 첨부 올리기, 초대 같은 것)이 막히고, 일상 업무는 그대로입니다.
- 결제가 처음 실패한 청구서가 60일 뒤에도 결제되지 않으면 **읽기 전용**이 됩니다. 보기, 내보내기, 결제, 닫기, 떠나기만 되고 그 밖의 쓰기는 모두 막힙니다. 밀린 청구서를 결제하면 풀립니다.
- 결제수단을 바꾸면 levyan이 다시 청구합니다. 결제되면 제한과 읽기 전용이 함께 풀립니다.

무엇이 막히고 무엇이 되는지는 [관리자·소유자 안내서의 결제](admin.md#결제-관리자-이상)에 있습니다.

### levyan이 답하지 않을 때

- levyan이 거절하면 그 말을 한국어 앞머리 뒤에 보입니다. 예를 들어 "결제 정보를 불러오지 못했습니다. 결제 서비스가 받지 않았습니다: …"입니다.
- levyan에 닿지 않으면 "결제 서비스에 지금 닿지 않습니다"입니다. 잠시 뒤에 다시 봅니다.

## 터미널에서

결제 화면의 일은 모두 `loft api payment` 입니다. 계정 자신의 호출이라 워크스페이스를 밝히지 않아도 됩니다. ID는 levyan의 것이라 문자열로 씁니다. 결제수단 등록(Paddle의 결제창)만은 브라우저에서 합니다. 비서(`loft mcp`)의 도구에는 아직 없습니다.

```sh
loft api payment list-billing-accounts
loft api payment create-billing-account '{"name": "이하은 개인", "country": "KR"}'
loft api payment get-billing-account '{"id": "<결제 계정 ID>"}'           # 수금 상태, 구독, 연체, 크레딧, 잔액
loft api payment update-billing-account '{"id": "<결제 계정 ID>", "name": "개발팀 카드"}'

loft api payment list-offers                                              # 받은 제안
loft api payment accept '{"offer": "<제안 ID>", "billing_account": "<결제 계정 ID>"}'   # 결제 계정은 나중에 정해도 됨
loft api payment decline '{"offer": "<제안 ID>"}'

loft api payment list-links                                               # 내는 워크스페이스
loft api payment use '{"workspace": "<워크스페이스 ID>", "billing_account": "<결제 계정 ID>"}'   # 다음 기간부터 이 결제 계정으로
loft api payment stop '{"workspace": "<워크스페이스 ID>"}'                 # 이번 기간이 끝나면 그만 내기

loft api payment list-invoices
loft api payment get-invoice '{"id": "<청구서 ID>"}'                       # 줄, 정정 청구, 연체
loft api payment list-credit-notes '{"billing_account": "<결제 계정 ID>"}'
loft api payment list-payer-statements
loft api payment get-payer-statement '{"id": "<명세서 ID>"}'               # 청구서 줄의 statement
```

워크스페이스의 ID는 `loft api party me -o json` 의 `tenant` 에 있습니다.
