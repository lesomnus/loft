# 감사자 안내서

감사자는 기록을 읽고 점검하는 사람입니다. 무엇이 언제 어디에 있었고 누가 가지고 있었는지, 누가 무엇을 바꿨는지, 누가 누구의 개인정보를 읽었는지를 봅니다. 바꾸는 일은 하지 않습니다. 이 문서의 예는 체험용 워크스페이스의 감사자 **박나은**(`naeun-park`)입니다([체험용 워크스페이스](README.md#따라-하기-체험용-워크스페이스)).

## 감사자가 할 수 있는 것

- **읽기**: 구성원이 읽는 것 모두(자산, 공간, 예약, 지급·대여, 재고, 실사, 작업, 구매, 사람)와 그 이력
- **리포트**: 자산 현황, 대여 현황, 예약 이용률, 실사 결과, 재고 소모와 그 CSV
- **설정 › 감사 기록**: 누가 무엇을 언제 바꿨는지
- **설정 › 접속기록**: 누가 누구의 개인정보를 읽고 쓰고 내려받았는지, 그리고 점검을 마쳤다는 기록
- 워크스페이스의 구성원 자격 목록, 계약, 법적 보존(hold)
- 모든 사람의 예약 이력

감사자는 예약하거나 고장을 신고하는 일도 하지 않습니다. 바꾸려 하면 `감사자 역할로는 할 수 없는 작업입니다` 로 거부됩니다. 감사 기록과 접속기록은 관리자 이상도 봅니다.

## 하루

### 그때 무엇이 어디에 있었나

- 자산 화면의 **이력**은 위치, 담당, 속성, 지급·대여, 작업이 언제 바뀌었는지를 시간을 따라 보입니다. 누가 했는지와 그 사유가 함께 나옵니다.
- **그때 시스템이 알던 대로 봅니다**는 나중에 정정된 기록을 빼고, 그 시각에 시스템이 보여 주던 모습을 봅니다. 정정한 기록도 지우지 않고 남기기 때문에 할 수 있는 일입니다.
- **공간**의 **시점 이동**은 과거 어느 때의 층과 방의 모습을, **두 시점 비교**는 그 사이에 무엇이 들어오고 나갔는지를 보입니다.
- 예약 창의 **이력**은 누가 예약·승인·취소·수령·반납했는지와 그 사유입니다. 감사자는 모든 예약의 이력을 읽습니다.

```sh
loft api asset search -o wide '{"q": "NB-002"}'
loft api asset timeline <자산 ID>                                     # 이력
loft api asset timeline <자산 ID> '{"superseded": true}'              # 정정되어 대체된 줄까지
loft api asset timeline <자산 ID> '{"known": "2026-10-01T00:00:00+09:00"}'   # 그때 시스템이 알던 대로
loft api asset query-at '{"root": {"id": "<4층 ID>"}, "at": "2026-06-01T00:00:00+09:00", "depth": 1}'
loft api asset diff '{"root": {"id": "<4층 ID>"}, "from": "2026-10-01T00:00:00+09:00", "to": "2026-11-01T00:00:00+09:00"}'
loft api reservation timeline <예약 ID>
```

### 작업 기록과 감사 기록

- **설정 › 작업 기록**은 무엇을 왜 했는지입니다. 사람이 한 일마다 한 줄이고, 자산 이력의 원천입니다. 문장은 읽을 때 만들고, 사람은 지금의 이름으로 부릅니다. 개인정보를 지운 사람은 가명으로 보입니다.
- **설정 › 감사 기록**은 모든 변경이 누가, 무엇을 바꿨는지 저절로 남는 기록입니다. 화면 아래의 "다음 페이지 ›"로 처음 것까지 거슬러 읽습니다.
- 감사 기록은 사람의 이름·연락처·사번, 초대 주소, 알림의 글, 사람의 말인 메모(지급·예약·작업·구매·실사의 메모, 점검 결과, 닫은 사유)를 값으로 남기지 않습니다. 바꿨다는 것만 남습니다.

```sh
loft api event recent '{"size": 20}'                       # 최근 작업 기록
loft api event recent '{"kind": "custody.issue"}'          # 한 종류만
loft api audit recent '{"size": 20}'                       # 최근 감사 기록 (next로 이어서)
```

### 접속기록 점검

개인정보를 읽거나 쓰거나 내려받은 호출마다 접속기록이 한 행씩 남습니다(loft#136). 워크스페이스의 관리자와 감사자는 한 달씩 점검합니다.

1. **설정 › 접속기록**을 엽니다. 처음에는 지난달을 엽니다. "‹ 이전 달", "다음 달 ›"로 옮깁니다.
2. **누가**(구성원), **누구의 정보**(정보주체), 종류(조회·수정·내려받기)로 좁혀 봅니다. 내려받기는 그 이유가 함께 보입니다.
3. 이상한 것이 없는지 본 뒤 **점검 결과**를 적고 **(그 달) 점검 완료로 기록**(예: "2026년 10월 점검 완료로 기록")을 누릅니다.
4. 누가, 언제, 어느 기간을, 그때 몇 건이었는지와 점검 결과가 남고, 작업 기록(`access.review`)에도 남습니다. 점검 기록은 고치거나 지울 수 없습니다.

- 남는 것은 누가, 언제, 어디서(접속지 주소), 어떤 기능으로, 누구의 정보를, 읽기·쓰기·내려받기 중 무엇을 했는지, 그리고 결과(거부 포함)입니다.
- 접속기록을 읽는 것도 사람의 이름을 보여 주므로 그 자체가 접속기록에 남습니다.
- 얼마나 보관하는지는 워크스페이스가 정하고(소유자의 설정 › 워크스페이스 › 기록 보관), 법이 정한 최소 기간보다 짧게는 정할 수 없습니다. 정하지 않으면 배포의 기간입니다.

```sh
loft api access review '{"from": "2026-10-01T00:00:00+09:00", "to": "2026-11-01T00:00:00+09:00"}'                     # 한 번에 92일까지
loft api access review '{"from": "2026-10-01T00:00:00+09:00", "to": "2026-11-01T00:00:00+09:00", "kind": "download"}'   # read, write, download
loft api access-review add '{"period_from": "2026-10-01T00:00:00+09:00", "period_to": "2026-11-01T00:00:00+09:00", "desc": "이상 없음"}'
loft api access-review ls -o wide
```

### 리포트

**리포트**의 다섯 표를 읽고 CSV로 내려받습니다. 무엇이 있는지는 [매니저 안내서의 리포트](manager.md#리포트)에 있습니다. 대여 현황의 CSV는 사람의 이름이 담기므로 내려받는 이유를 묻고, 그 이유는 접속기록에 남습니다.

```sh
loft api asset census '{"by": "location"}'
loft api custody outstanding '{"overdue": true}'
loft api --reason "10월 대여 점검" custody export-outstanding -o 'template={{.data}}' | base64 -d > 대여.csv
```

### 계약과 법적 보존

워크스페이스가 파기될 때 감사 기록을 어떻게 할지는 배포 운영자와의 계약이 정하고, 법적 보존(hold)이 걸려 있는 동안은 아무것도 지우지 않습니다. 둘 다 운영자가 걸고, 워크스페이스에서는 읽기만 합니다.

```sh
loft api tenant-contract ls -o wide
loft api legal-hold ls -o wide
```

## 운영자에게 요청할 것

- **배포 전체의 접속기록**, 그리고 정보주체가 자기 정보의 처리 내역을 물었을 때 뽑는 것은 운영자가 합니다(`loft access ls --subject`).
- **작업 기록의 사유 삭제**: 어떤 작업 기록의 사유가 그 사람에 관한 것이라 지워 달라는 요청이 오면, 워크스페이스의 지시로 운영자가 지웁니다. 무엇을 언제 누가 했는지는 그대로 남습니다.

어떻게 하는지는 [배포 운영자 안내서](operator.md#감사-기록과-접속기록)에 있습니다.
